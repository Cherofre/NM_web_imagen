# 1.1.4 桌面更新检查（2026-09-17）

## 已确认的问题

- GitHub 当前最新正式版为 v1.1.3。该 Release 只有四类手动分发包及各自的 manifest/SHA256，共 12 个附件。
- 旧客户端使用 `/releases/latest/download/latest.json` 和 `portable-latest.json`。实测两者都是 HTTP 404，因此当前旧客户端不能依赖自动检查收到新版提醒。
- 原先自动检查只在启动 7 秒后执行一次，距上次成功检查不足 24 小时则跳过；长期开着不会再次检查。提醒是窗口内横幅，不是系统通知。
- Rust 事件实际为 `started/progress/finished`，前端却监听 `Started/Progress/Finished`，且 Rust 枚举字段缺少 camelCase 转换，导致进度无法更新。
- 用户提到的历史下载失败没有完整日志；不能把 404 或进度问题断定为那一次失败的全部原因。当前未确认原签名私钥位置，1.1.1 发布记录已经说明密钥缺失。

## 1.1.4 改动

- 签名更新源失败时，通过固定 GitHub Releases API 查询公开正式版，使用 SemVer 比较。发现新版本会显示窗口内提醒和手动下载指引。
- 此兜底只发现版本、打开固定发布页，不会绕过 Tauri 签名校验下载执行程序。安装版使用 Setup；便携版使用 Portable ZIP，退出后替换程序文件，保留 data。
- 启动 7 秒后检查，并每小时检查是否已达到 24 小时检查间隔。检查失败不会记为成功，下次轮询可以重试。
- 前端阻止重复检查/下载/安装；等待安装或已下载便携包时不重新检查以免丢失状态。
- 修复事件名称和进度字段协议；检查超时 20 秒，完整包下载超时 15 分钟。下载失败提供发布页手动下载指引。

## 与 DSH Desktop 的对照

参考源码：
- https://github.com/anywhere-labs/dsh-desktop/blob/master/dsh-plugin-desktop/src/update-checker.ts
- https://github.com/anywhere-labs/dsh-desktop/blob/master/dsh-plugin-desktop/src/update-lifecycle.ts
- https://github.com/anywhere-labs/dsh-desktop/blob/master/dsh-plugin-desktop/src/update-download.ts

DSH 使用自有域名的版本 API 和下载 API；生命周期模块拥有定时检查、超时取消、并发去重和“同一版本只通知一次”的系统提醒。用户同意下载后再次确认目标版本，下载模块检查版本/大小/安装包结构并使用临时文件。它不是直接套用 Tauri updater。

本项目采用可独立获取的改进：版本发现与签名安装分离、定时重查、操作去重、手动下载兜底。继续使用 Tauri 对应用内安装包验签；没有照搬 DSH 的基础设施、系统通知或平台安装实现。

## 旧客户端的边界

1. 1.1.4 本地打包不会让 1.1.3 及更早的已安装程序自动获得新代码。
2. 要恢复旧客户端的应用内更新，需要找回与内置公钥匹配的原私钥，生成签名包和两个 feed，并把它们发布到最新正式 Release。
3. 新建一把私钥不能让旧公钥信任新签名；不要为了“能下载”关闭验签。
4. 未找回原私钥时，旧用户需要手动安装一次 1.1.4。之后 1.1.4 可以通过 GitHub API 发现更高版本并提供手动升级提醒。
5. 尚未完成真实旧版本安装、替换、重启的端到端升级验证；发布 Release 不改变此边界。
