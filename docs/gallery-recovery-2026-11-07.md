# 历史图库404恢复与切换目录保护

## 事实与原因

2026-11-07 用户安装试用版后报告历史图片加载失败。实际运行的安装版后端仍使用 `D:/Documents/NM Image Studio`，截图原图 `20261015-163528-304927-gpt-image-2-01.png` 请求404。该目录当时只有632字节的新建空会话文件，原图片、历史及17个会话位于同级 `NM Image Studio.backup-1794023789`。

备份后缀对应11:56:29，安装程序时间12:02:35。可以确认目录已被移到备份，不能说安装器删除了原图。Rust `desktop_set_outputs_directory` 原实现使用 `replace_directory_contents(current,target)`：先改名备份目标，再复制当前目录。新建空目录作为来源时，选择已有图库就会用空会话替换原位置，所有旧图片URL失效。这是既有目录切换逻辑的缺陷，此前安装包验收未覆盖“目标已含真实图库”的场景。

## 已执行的恢复

1. 将确认的备份逐文件补回当前目录，使用独占新建模式，已有文件一律不覆盖。共167文件、465,972,817字节；原备份完整保留。
2. 第一阶段保留当前 `studio_sessions.json` 字节不变，随后通过实际后端 GET/PUT 会话接口按 `expected_revision` 合并17个缺失会话，保留当前已有会话和内容。最终18个会话、121轮，revision由2更新到3。并另存合并前当前会话到本地诊断目录。
3. 实际安装版后端对截图原图与11/7小狗原图均返回200，内容逐字节匹配备份；图片URL的桌面查询令牌授权也已验证200。
4. 扫描恢复后会话与历史的161个唯一图片URL，159个返回有效图片（200/206）。其余两个旧文件在备份、工作区输出、AppData两种桌面目录、其他已知D盘备份和60个有界候选布局中未找到：
   - `20260910-204720-570251-gpt-image-2-01.png`
   - `20260910-205325-889956-gpt-image-2-01.png`

这两张旧图仍未找回，不伪造图片或删除其记录。证据：`.runtime/image-recovery-20261107.json`、`.runtime/image-references-20261107.json`。

## 防复发改动

- 更换存图目录仅允许迁移到空目录。目标非空时明确拒绝，不改名、不备份替换、不更新路径配置；用户主动确认的「导入旧数据」流程保持原有独立边界。
- 向空目录复制使用 `create_new`，即使检查后出现同名文件也不覆盖；源目录保留。
- 同目录与嵌套判断解析真实已有父目录，统一Windows扩展路径、短路径/目录链接与普通路径；消除 `..`，避免路径别名绕过保护。
- 桌面设置说明改为明确要求空文件夹。
