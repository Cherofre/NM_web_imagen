# NM Image Studio v1.1.0 Windows 桌面版实施计划

## 技术验证结论（2026-08-17）

结论：继续采用 **Tauri 2 + 现有 React/Vite + FastAPI PyInstaller `onedir`**。这是当前项目综合改造成本、运行体积、Windows 集成能力和后续维护成本后最合适的桌面方案。

已在分支 `codex/desktop-spike-v1.1.0` 实测通过：

- Tauri 2 release 编译和真实 Windows 窗口启动。
- FastAPI `onedir` 后端由 Rust 启动，使用随机 `127.0.0.1` 端口和每次启动随机令牌。
- 固定 Tauri 前端来源下，配置、历史和 Studio 会话 API 均可正常读取或写入。
- 桌面模式未携带令牌访问 `/api/health` 返回 401；网页模式保持原兼容行为。
- 前端 `apiFetch()` 自动补后端地址和请求头令牌；输出图片 URL 自动补随机端口和短期查询令牌。
- 首次启动在独立数据目录中没有配置时，工作台正常显示并打开配置界面。
- 关闭主窗口后，Tauri 壳、FastAPI 后端和随机端口均无残留。
- Python 248/248、前端 164/164、尺寸规则、Python 编译、Vite 构建、`cargo check --offline`、sidecar 独立烟测和真实桌面烟测通过。

实测分发负载：

- Tauri 壳 EXE：约 8.14 MiB。
- PyInstaller 后端目录：约 58 MiB，708 个文件。
- 不含 WebView2 Runtime 的运行负载：约 66.14 MiB。

因此正式分发应采用：

1. **安装版**：用户下载一个 Setup EXE；安装后内部仍是正常应用目录。
2. **便携版**：一个 ZIP，解压后运行整个文件夹。
3. **网页版**：继续提供现有 Win64 离线文件夹/ZIP。

不应追求真正的“运行时单 EXE”。PyInstaller `onefile` 在本机验证中出现长时间自解压和父子进程滞留，且每次启动都要释放完整 Python 环境；`onedir` 启动更稳定，也更利于增量更新、杀毒白名单和故障诊断。单个 Setup EXE 只是安装入口，不等于安装后的应用只有一个文件。

当前正式分支仍未完成或不能宣称：托盘、通知、更新器、旧数据迁移、原生另存为、固定 WebView2 Runtime、无 WebView2 机器上的实机验收、DPI 矩阵、剪贴板/拖放/遮罩全流程人工验收和安装器。已完成桌面设置、快捷键、窗口状态、常用路径操作、默认无控制台启动、可选启动时后端控制台、设置内按需打开的实时后端调试窗口、单实例、Job Object 异常退出兜底、DPAPI、便携 ZIP 生成/解压启动烟测和 WebView2 缺失启动提示代码。

## 按需后台调试窗口（2026-08-18）

正式 EXE 默认保持无黑窗。需要查看后台时，在 `桌面设置 → 存储与日志` 点击 `打开调试窗口`，桌面壳会启动一个独立 PowerShell 窗口，实时跟踪固定的 `desktop-backend.log`，保留最近 200 行并继续等待新日志。

- 不重启 FastAPI，不改变当前随机端口或桌面令牌，也不中断正在执行的任务。
- 前端不传入日志路径；Rust 只使用受管状态中的 `log_path`，通过子进程环境变量传给固定脚本，避免路径注入和任意文件跟踪。
- 后端使用 `PYTHONUNBUFFERED=1`，重定向到日志文件时新请求可以及时出现。
- 调试窗口加入现有 Windows Job Object。手动关闭调试窗口不会影响主应用；关闭主应用时不会留下孤立的 PowerShell 跟踪进程。
- 原有 `定位日志` 仍保留，适合只想在资源管理器中打开日志文件的场景。

## 桌面配置的 DPAPI 保护（2026-08-18）

桌面 sidecar 启动时设置 `IMAGE_TOOL_DESKTOP_MODE=1`。在这个模式下，后端仍向前端返回原有配置结构，API Key 只在进程内存中以明文参与请求；落盘时则写成 Windows 当前用户范围的 DPAPI 密文，格式为 `dpapi:v1:<base64>`。

- 网页模式不改变，继续兼容现有明文 `config.local.json`。
- 已有桌面数据目录中的明文配置在第一次读取时解密兼容并原地迁移为 DPAPI 密文。
- 写入桌面配置不使用会复制旧明文的通用备份路径；如果存在 `.bak`，会用新的加密内容覆盖它。
- DPAPI 无法解密时不会把密文当作 API Key 发往上游，而是返回配置加密/解密错误，要求用户在当前 Windows 用户下重新输入 Key。
- DPAPI 绑定当前 Windows 用户。换用户或换电脑后，配置结构、模型和 URL 仍可迁移，但 API Key 需要重新输入。

## 便携 ZIP 与 WebView2 启动检查（2026-08-18）

- `scripts/package_desktop_portable.ps1` 从 release 目录收集壳 EXE 和完整 `backend\`，加入 `portable.mode`，生成 `NM-Image-Studio-v<版本>-Portable-x64.zip`，并在 ZIP 旁输出 manifest 与 SHA256 文件。
- 便携标记存在时，桌面配置、会话、历史、日志、引用和成图全部写入 EXE 同级 `data\`；没有标记的安装版继续写入 Tauri per-user app-local data 目录。
- `scripts/smoke_desktop_portable.ps1` 会解压 ZIP、检查壳/sidecar/标记并启动 EXE，确认便携 `data\` 在启动时创建。
- Windows 启动 Tauri 前查询 WebView2 Evergreen Runtime 的 EdgeUpdate 注册表客户端键。缺失时显示中文错误窗口和官方安装入口后退出；当前默认包不携带固定 WebView2 Runtime。

前端构建链当前还有 5 个 `npm audit` 报告（2 low、3 high），集中在 Vite/PostCSS/esbuild/Babel/nanoid 的开发构建或开发服务器路径。当前兼容范围内 `npm audit fix` 无可应用变更，且这些 Node 依赖不会进入约 66 MiB 的桌面运行目录；正式 v1.1.0 发布前仍应单独升级到已修复的 Vite 主版本并重跑完整矩阵。

## 桌面技术栈复评

| 方案 | 适配度 | 结论 |
| --- | --- | --- |
| Tauri 2 + FastAPI `onedir` | 高 | 最大限度复用现有 React/FastAPI，壳小，Windows 集成和更新能力完整；保留为正式方案。 |
| Electron + FastAPI | 中 | 开发成熟，但会再携带 Chromium/Node，体积和内存明显更高；本项目没有足够收益抵消成本。 |
| .NET/WPF/WinUI + WebView2 | 中 | Windows 原生能力好，但需要新建和长期维护 C# 宿主层；对当前团队和代码基线改造过重。 |
| pywebview + FastAPI | 中低 | Python 优先、验证快，但窗口生命周期、安全桥接、更新和安装生态弱于 Tauri，体积也不会显著小于当前 Python sidecar。 |
| PySide6/QtWebEngine | 低 | 打包体积通常更大，还会引入 Qt 界面/浏览器运行时；与现有 React 前端重复。 |
| Neutralino 等轻量壳 | 低 | 壳很小，但 Windows sidecar、更新、长期生态和安全边界不如 Tauri 稳妥。 |

正式实施继续以 Tauri 为主，不需要为了“单文件”改成 Electron、C#、全 Rust 或 Qt。

## 总体方案

- 保留现有 React 19 + Vite 7 + FastAPI，不重写业务，不换成 Electron、C# 或全 Rust。
- 新增 Tauri 2 作为 Windows 桌面外壳，负责窗口、托盘、更新、原生文件选择和 Python 后端生命周期。
- FastAPI 通过 PyInstaller `onedir` 打包成无控制台 sidecar。
- 分两阶段开发：
  1. `codex/desktop-spike-v1.1.0`：验证 Tauri、WebView2、Canvas、拖放、剪贴板、sidecar。
  2. `codex/desktop-v1.1.0`：完成正式功能、迁移、更新和发布。
- Tauri 验证若存在无法解决的 P0 问题，停止并提供证据，不自动切换技术栈。

## 桌面架构与窗口

- Tauri 加载内置 React 静态资源，使用固定应用来源，避免随机后端端口导致 `localStorage` 变化。
- Rust 启动 FastAPI 时：
  - 绑定 `127.0.0.1` 随机端口。
  - 每次生成随机桌面令牌，通过环境变量传递。
  - 等待带令牌的健康检查通过后进入工作台。
  - 使用 Windows Job Object 和父进程监控，主程序异常退出时清理后端。
  - 正常退出先请求 FastAPI 刷盘并关闭，超时后强制清理。
- `/api/**` 在桌面模式下必须携带请求头令牌，并只允许固定 Tauri 来源；`/outputs/**` 保持只读，但也必须携带请求头令牌或当前启动周期的查询令牌。
- 单实例运行：重复启动时聚焦现有窗口。
- 默认窗口 1440×900，最小约 760×640，自由缩放并记住尺寸、位置和最大化状态。
- 使用 Windows 原生标题栏，不做自绘标题栏。
- 标准最小化进入任务栏；关闭窗口才根据关闭偏好处理。

## 前端与桌面界面

- 保留现有黑白灰气质、会话栏、历史、工作区、输入区和遮罩工作流。
- 压平最外层网页卡片，减少外层圆角、阴影和留白，缩短页头，让内容更像桌面工作台。
- 只拆分桌面版必需边界：
  - 运行时客户端和 `apiFetch()`。
  - 桌面桥接与输出地址处理。
  - 启动状态页。
  - 设置页和迁移页。
  - 工作台主体不进行全面组件重构。
- 桌面版配置按钮跳转到主窗口内的完整设置页；返回时恢复原会话、滚动位置和输入内容。
- 设置页采用左侧分类、右侧内容结构，窄窗口下改为顶部分类选择，避免嵌套卡片。

设置分类：

1. 连接与模型
   管理配置档、URL、模型和 API Key。
   “保存配置”和“测试连接”完全独立；保存不会自动调用测试接口。生图、聊天测试仍可分别手动执行。

2. 默认生成
   只控制新建会话的初始尺寸、数量、质量等参数。修改默认值不影响已有会话，工作区参数始终优先。

3. 存储与迁移
   显示数据目录、成图目录，提供打开目录、更换成图目录、导入旧版数据和清理缓存。

4. 应用与窗口
   语言、关闭行为、后台完成通知、恢复窗口布局。本版不加入开机启动。

5. 更新、关于与诊断
   版本信息、检查更新、内部更新源、WebView2/后端版本、打开日志、复制脱敏诊断信息。

保存规则：

- 语言、窗口、通知和更新开关立即保存。
- 更换目录通过单独确认流程执行。
- 连接配置点击“保存配置”后保存。
- 默认生成参数点击“保存默认值”后保存。
- 所有新增文案同时补齐中英文 i18n。

## 数据目录与兼容

新增统一 `StoragePaths` 抽象，替换 `app.py` 中直接依赖项目目录的常量。

安装版：

- 配置、会话、历史、日志、内部引用：Tauri 稳定应用目录 `%LOCALAPPDATA%\com.nmimagestudio.desktop`
- 默认成图目录：Windows“图片”已知目录下的 `NM Image Studio`
- 使用 Windows Known Folder API，不依赖中文或英文系统文件夹名称。

便携版：

- 使用程序旁的便携标记识别模式。
- 配置、会话、历史、日志、内部引用和成图全部放在 `data\`。
- 搬到另一台电脑后，除 API Key 外的数据继续可用。

网页便携版：

- 继续使用当前项目目录、`config.local.json` 和 `outputs\`。
- 现有启动脚本、API、历史和 `/classic` 兼容路径保留。
- Classic 不作为桌面版入口，也不新增 Classic 功能。

输出路由调整：

- `/outputs/<file>` 映射到当前成图目录。
- `/outputs/session_refs/<file>` 映射到内部引用目录。
- 继续保留原有 URL 形式，旧历史、旧会话和遮罩引用不需要批量改写。
- 删除、复制参考图、再次生成、历史预览等操作统一通过路径抽象解析，禁止回退到任意文件访问。

## API Key 安全

- 安装版和便携版都使用 Windows DPAPI 当前用户范围加密。
- Python 侧使用 Windows 系统 API 完成加解密，不额外依赖在线服务。
- 桌面配置文件不保存明文 Key。
- 桌面配置接口只返回：
  - 是否已保存 Key。
  - 脱敏尾号。
  - 是否因换电脑或换用户而需要重新输入。
- 保存配置时：
  - 输入新 Key：替换加密值。
  - Key 留空：保留现有值。
  - 只有显式“清除 Key”才删除。
- 从旧版导入明文 Key 时，在写入新目录前立即转换为 DPAPI 密文。
- 旧目录坚持只读复制，不自动删除；迁移完成后提醒旧 `config.local.json` 可能仍含明文 Key。
- 便携目录换电脑或 Windows 用户后只要求重输 Key，不影响会话、历史和成图。

## 旧数据迁移

首次启动候选来源：

- 安装器启动目录附近的旧版目录。
- 便携程序自身和相邻目录。
- 用户手动选择的目录。
- 不扫描整块磁盘，不硬编码任何 `G:\` 路径。

发现有效旧数据时：

- 显示旧目录、配置数量、会话数量、历史数量、图片数量和总大小。
- 主操作为“一键导入并继续”。
- “选择内容”可单独控制配置、会话、历史和成图；关联的遮罩及 `session_refs` 自动跟随。
- 日志、缓存、队列状态、输入框高度、语言等浏览器专属轻量偏好不迁移。
- 用户选择暂不导入后，不再对同一候选反复弹出；设置页仍可手动导入。

安全规则：

- 导入只复制，不删除源数据。
- 开始前检查目标目录权限和磁盘空间。
- 相同内容通过哈希去重。
- 同名但内容不同的文件自动改名，并同步修正导入记录。
- 同 ID 但内容不同的会话或历史生成新 ID，两份都保留。
- JSON 先写临时文件，校验后原子替换；已有目标文件先做时间戳备份。
- 失败时保持当前有效数据不变，展示失败文件并支持重试。
- 更换成图目录使用同一套复制和校验机制：先复制已有成图，验证成功后再切换，旧目录保留。

## 新增接口与类型

前端运行时层：

- `RuntimeMode`: `web | desktop-installed | desktop-portable`
- `RuntimeInfo`: API 地址、桌面令牌、版本、运行模式、数据路径和可用能力。
- `apiFetch()`: 桌面模式自动添加 API 基址和令牌，网页模式保持当前相对请求。
- `resolveOutputUrl()`: 处理网页和随机桌面后端的图片地址。
- `downloadOutput()`: 网页模式下载，桌面模式打开原生“另存为”。
- `desktopBridge`: 目录选择、打开目录、托盘、退出、通知和更新的统一封装。

FastAPI 新增桌面专用接口：

- `GET /api/desktop/settings`
- `PUT /api/desktop/settings`
- `POST /api/desktop/transfers/scan`
- `POST /api/desktop/transfers`
- `GET /api/desktop/transfers/{job_id}`
- `POST /api/desktop/transfers/{job_id}/cancel`
- `POST /api/desktop/shutdown`

传输任务统一支持旧数据导入和成图目录切换，返回阶段、文件进度、字节进度、冲突、失败项和最终报告。

现有配置接口在桌面令牌模式下返回脱敏 Key 状态；网页模式继续保持旧版兼容格式。

## 更新和发布

详细方案见 [`NM-Image-Studio-desktop-updater-plan.md`](./NM-Image-Studio-desktop-updater-plan.md)。当前推荐边界为：

- 启动稳定后最多每 24 小时自动检查一次，手动检查不受限制；用户可以关闭自动检查。
- 发现新版本时显示顶部轻提示，不弹启动模态框；“稍后提醒”对同一版本暂停 24 小时。
- 第一阶段仅使用 GitHub Releases 稳定渠道，不同时实现 UNC、自定义 URL 和多渠道回退。
- 安装版使用 Tauri 2 官方 updater、Tauri 签名和普通联网 NSIS 更新包；有任务时可以检查和下载，但不能安装重启。
- 便携版检查同一版本并下载完整 ZIP，验证签名和 SHA256，提示保留 `data\` 后手动替换；不在运行中覆盖当前 EXE 或 `backend\`。
- 网页端不进入桌面更新器边界，桌面更新不会读取、停止或替换网页 ZIP、7861 端口及网页数据目录。
- 第一版提供可恢复失败路径和旧版本手动恢复入口；真正自动回滚需要独立 updater helper，不能仅依靠主程序或 Tauri updater 宣称完成。

离线运行：

- 默认安装版和便携版使用系统已有的 WebView2 Evergreen Runtime；Windows 10/11 的常见环境通常已经具备。
- 启动前检测 WebView2，缺失时给出明确中文提示和离线安装入口，不显示无解释白屏。
- 另提供可选的完整离线安装包，携带 WebView2 Evergreen Standalone Installer，供封闭网络或批量部署使用。
- 只有明确需要“解压后在无 WebView2、无网络机器上直接运行”时，才制作携带固定 WebView2 Runtime 的大体积便携包。
- 固定 Runtime 会使包体达到数百 MB，不应作为所有用户的默认下载负担。

发布产物统一使用根目录 `VERSION` 作为版本源：

- `NM-Image-Studio-v1.1.0-Setup-x64.exe`（普通联网安装器）
- `NM-Image-Studio-v1.1.0-Offline-WebView2-Setup-x64.exe`（内嵌 WebView2 安装器）
- `NM-Image-Studio-v1.1.0-Portable-x64.zip`
- `NM_web_imagen-v1.1.0-Web-x64.zip`
- 更新清单、签名文件和 SHA256 清单

四种产物已通过版本/哈希/内容隔离验证。网页包继续使用现有 `start_web.ps1` 和默认 `127.0.0.1:7861`；桌面安装版使用 Tauri 随机 loopback sidecar 端口和 `%LOCALAPPDATA%`，桌面便携版使用 EXE 同级 `data\\`。两端不共享运行目录、配置、日志或端口。

当前没有 Authenticode 证书：

- 安装包可能触发 SmartScreen。
- 使用 GitHub HTTPS、Tauri 更新签名和公开 SHA256 保证下载完整性。
- 不使用没有实际信任价值的自签名证书。
- Authenticode 作为后续发布能力处理。

## 实施顺序

1. 建立 Tauri 技术验证分支，验证固定来源、随机端口、sidecar、拖放、剪贴板、遮罩 Canvas、原生保存、DPI、单实例和退出清理。
2. 建立正式分支，加入运行时客户端、桌面桥接和最小前端拆分。
3. 完成后端路径抽象、输出路由、令牌验证、DPAPI 和桌面设置。
4. 完成启动页、设置页、迁移流程、托盘、关闭保护和后台通知。
5. 完成安装版、便携版、WebView2 离线运行和更新流程。
6. 跑完整兼容矩阵，生成三个发布包、签名和哈希。
7. 用户验收后再合并、打标签、发布 GitHub Release；G 盘同步仍作为明确授权后的发布步骤，不写入程序逻辑。

## 测试与验收

- 回归现有 Python、前端、遮罩、历史、会话、批量图片、配置兼容和发布测试。
- 验证网页模式所有请求仍为同源相对请求，现有启动器兼容 PowerShell 5.1。
- 验证桌面 API 无令牌、错误来源和路径穿越均被拒绝。
- 验证随机后端端口变化不会丢失桌面 `localStorage`。
- 验证安装版和便携版在无 Python、Node、Rust、WebView2 和无网络环境下启动。
- 验证中文用户名、中文目录、空格路径和超长路径。
- 验证 100%、125%、150%、200% DPI，以及 1440×900 和最小窗口布局。
- 验证参考图拖放、剪贴板粘贴、遮罩画笔、缩放、撤销、再次生成、复制参考图和历史遮罩回看。
- 验证正常退出、崩溃退出、重复启动、托盘恢复和 sidecar 无残留。
- 验证迁移完整、取消、失败重试、空间不足、冲突保留、源目录不变。
- 验证便携目录换电脑后仅 Key 需要重新输入。
- 验证成图目录切换后旧历史图片仍可打开。
- 验证安装更新、便携下载、签名失败、下载失败回退和任务中禁止安装。
- 验证发布包不包含本地 Key、用户输出、日志、缓存和开发依赖。
- 自动测试使用模拟上游；真实付费生图只在用户明确授权后执行。

## 明确不包含

- macOS、Linux、Windows ARM64。
- 多窗口和多个桌面实例。
- 开机自动启动。
- 文件关联和右键菜单。
- 持久化后端任务队列重构。
- 全面拆分 6000 行工作台组件。
- Classic 桌面入口。
- 静默自动更新。
- 自动扫描浏览器数据库或迁移浏览器轻量偏好。
- Authenticode 代码签名。
