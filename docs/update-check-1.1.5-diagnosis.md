# 1.1.5 更新检查核查（2026-10-14）

用户反馈：已勾选自动检查，打开1.1.5没有新版本提示；手动检查界面可以显示1.1.6，但只能去下载页。

## 代码与发布证据

- 对v1.1.5标签中的实际App与desktopUpdater.ts执行纯事件模拟：启用自动检查时启动7秒后触发调度；从未成功检查/超过24小时会调用检查，1小时内成功检查过则不会调用；关闭自动检查不注册定时器。后台每小时调度，但同样受24小时成功检查间隔限制。
- 实际handleDesktopCheckUpdate(true)遇到模拟网络错误后设置failed状态和错误文本，却不弹notice；错误可在关于/更新设置看见，主界面没有失败提示。
- “稍后提醒”按版本压制提示24小时；新版本号与旧版本号不同不会继承旧版本的压制。
- 当前1.1.6 GitHub Release的12附件没有latest.json、portable-latest.json、Updater及签名文件。当前Tauri请求latest下载端点取签名feed，失败后查Release API，将结果标为manualDownload且无可安装packageUrl；因此只显示下载页入口。
- 自动检查开关不表示自动下载。已有前端下载/进度、Rust下载和安装命令，但需要可验签feed/包才能使用；目前没有取得与内置公钥匹配的发布私钥，不能把旧feed换个版本号或关闭验签。

## 对用户这次现象的判断

没有读取用户1.1.5实际WebView的上次检查/稍后提醒记录，不能断言该实例已经请求或失败。若当天成功检查过，则当天新发布版本不会因重开程序立即发现，这是当前节流设计造成的体验问题；手动“检查更新”绕过自动调度间隔，可以立即发起检查。

以上为源代码实际执行和远端附件核查，未冒充原生GUI点击或本机旧版进程日志。此次没有改更新策略、签名公钥或覆盖已发布1.1.6。后续可考虑每次启动检查、后台较短间隔及明确的检查失败提示；恢复应用内下载安装须先解决签名发布链路。
