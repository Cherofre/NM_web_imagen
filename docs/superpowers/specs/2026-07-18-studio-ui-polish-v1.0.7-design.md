# Studio UI 全面精修设计（v1.0.7）

## 背景

当前 Studio 已具备完整生图、聊天、队列、历史、参考图和遮罩工作流，但真人截图评审显示五类界面问题：结果缩略图过小且会裁切竖图；顶部和输入区同时暴露过多控制；重复或图标化操作难发现；胶囊和黑色强调使用过多；会话、内容和输入区缺少统一对齐骨架。

本次是现有 Studio 的生产级精修，不是视觉重做。保留 React/Vite + FastAPI 架构、三栏工作台、黑白灰基调、现有数据和接口行为。

## 目标

1. 让生成结果成为页面视觉中心，并保证缩略预览不歪曲真实构图。
2. 将每个主要决策点控制在约四组可见操作内。
3. 让首次使用者不依赖记忆图标即可理解主要动作。
4. 用控件形状和强调级别表达语义，而不是让所有内容都像胶囊按钮。
5. 让侧栏、会话内容和输入区在宽屏、窄屏和 200% 缩放下保持清楚对齐。

## 设计决策

### 1. 结果展示

- 单张结果默认展开，不显示“展开 1 张图片”。
- 单图按真实宽高比展示，使用 `object-fit: contain`；竖图、横图和方图分别设置合理最大宽度。
- 多图仍允许紧凑折叠，折叠缩略图可使用统一比例，但展开后必须完整显示构图。
- 结果主操作显示文字：`继续编辑`、`编辑遮罩`、`下载`；复制提示词、套用提示词、作为参考图和新窗口打开收进“更多操作”。
- 操作栏进入正常文档流，不再靠绝对定位悬在图片下方。

### 2. 控制层级

- 左侧只保留一个“新对话”主入口，移除重复入口。
- 顶部保留模型、当前配置和语言；`保存配置`只在配置抽屉内出现。
- `清空`移入顶部更多菜单，改名为`清空当前对话`并使用危险操作样式。
- 输入区保留模式、参考图、`生成设置`、高级参数四组入口。
- 尺寸、质量、数量合并进一个生成设置弹层，保留原参数能力和多图风险提示。

### 3. 视觉系统

- 收紧全局圆角 token；胶囊只用于真实切换器、状态和短标签。
- 普通按钮、配置入口和菜单使用 10–14px 圆角。
- 每个区域只保留一个黑色主动作：侧栏的新对话、主工作区的发送、抽屉的保存。
- 队列入口改为稳定的中性状态控件；运行时显示`队列`和活动数，完成后显示`最近任务`和保留条数。
- 缩短高级参数提示，避免悬浮说明遮住参考图与参数栏。

### 4. 布局与侧栏

- 会话数量与列表包进同一伸缩区域，列表从数量下方开始，不再被推到侧栏底部。
- 会话内容使用统一的中心内容宽度；输入区内部与会话列使用同一宽度和左右边界。
- 保留大画布留白，但由更清楚的内容列和更大的结果承载视觉重心，不新增无关面板。

## 兼容性与风险

- 不改变后端 API、提交载荷、配置 schema、历史/session schema、队列和遮罩协议。
- 不移除 `/classic`，不增加第三方前端依赖。
- 顶部保存入口移除后，配置抽屉中的保存入口仍为唯一可靠路径。
- 单图默认展开会增加单轮纵向高度，但会显著提高结果可读性；多图折叠保持原有密度。
- 现有前端测试大量依赖源码/CSS 结构，必须同步更新为新的行为契约，不能简单删除断言。

## 验收标准

- 竖图在结果区完整可见，不被裁成 4:3；单图默认展开且无冗余展开按钮。
- 结果区直接可见三项带文字主操作，其他动作位于可键盘访问的更多菜单。
- 顶部没有重复保存按钮，清空当前对话位于更多菜单并有危险样式。
- 输入工具栏只显示模式、参考图、生成设置、高级参数；尺寸/质量/数量能力完整保留。
- 侧栏会话卡片紧跟数量显示；会话内容和输入区共享内容宽度。
- 关键按钮具备 hover、active、focus、disabled/loading 状态；触摸设备目标不小于 40px，主要动作尽量接近 44px。
- 中英文文案同步，减少动态效果设置仍有效。
- Node 全量、尺寸门禁、TypeScript/Vite build、发布/缓存门禁和当前验收服务资源 smoke 全部通过。
