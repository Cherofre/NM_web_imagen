# 1.1.3 审查记录

日期：2026-09-10。范围：1.1.2 发行包、Windows 桌面拖拽、参考图请求及跨机环境依赖。

## 已定位并修复

1. Windows 拖拽被 Tauri 默认拖拽处理接管，React 的 HTML5 上传处理收不到事件。主窗口设置 dragDropEnabled=false，沿用网页端的图片上传和参考图排序逻辑。当前安装依赖的 schema 和 [Tauri 官方配置说明](https://v2.tauri.app/reference/config/) 均说明 Windows HTML5 拖拽需要此设置。
2. 上游返回 Unknown parameter 时，会自动删除任意 payload 字段重试。现保护 model、prompt、image、input、tools、n，避免参考图或核心生成意图被静默丢弃。仅不支持的可选参数继续兼容重试。回归模拟不支持 image 的上游，验证只请求一次并返回失败。
3. 启动保护提示超过 6 秒后停止检测，慢电脑之后成功渲染也不能消除错误提示。现在持续检测并自动移除提示，已补行为测试。
4. 桌面壳初始化失败原先 expect/panic，隐藏控制台的发行版无可见错误。现在显示原生启动错误窗口，后端启动超时带日志路径。
5. 便携烟测原先清理所有同名后端进程，已改为由当前 shell 的 Job Object 清理自己启动的进程；恢复原有浏览器调试环境变量和 PATH；解压清理限定临时目录。

6. 实际网页请求发现 `/boot-guard.js` 为 404：入口相对路径没有根路由映射。已补静态路由、no-cache 与真实 HTTP 回归。
7. 干净便携目录启动却读到安装版的 17 个会话：Tauri 默认 WebView 存储按应用标识共用。便携版现在延后创建主窗口，用 builder 的绝对 data_directory 指向 `data/webview`，与后端 data 一起隔离。安装版存储路径保持原样。旧便携版后端已保存的数据仍从 data 读取，浏览器内的临时偏好从独立配置开始。

## 参考图异常的证据与边界

用户截图对应本机历史：2026-09-10 20:47:20 与 20:53:26 的「YS」gpt-image-2.5-sunburst，以及 20:57:44 的「KB」gpt-image-2，均记录 /v1/images/edits、4 张参考图、请求尺寸 2880x2880。截图中 sunburst 的返回结果为 1024x1024。

新增 API 回归分别使用两个模型名和四张不同像素的 PNG，捕获请求并验证：保持模型名，使用 edits，四个 image[] 文件字节完整且顺序一致，不插入额外模型调用。说明当前客户端没有按模型名丢图的分支。

这些证据不等于上游实际接收和使用了所有图片。历史没有保存线上完整请求体，未重放付费生图，不能断言 sunburst 的真实故障根因。更可能需要渠道核对该别名的图像编辑、多图和尺寸支持。此次防丢参数修复属于另一个真实缺口，不宣称它解释了截图里的 edits 请求。

## 兼容范围

Windows 10/11 x64，使用当前受支持的 WebView2 Evergreen。新电脑推荐离线安装版。桌面包内含 Python 3.12 DLL、OpenSSL DLL、VC runtime；网页包内含嵌入式 Python 和依赖轮子，无需系统 Python/Node/Rust。便携桌面版本身不携带 WebView2，不能称完全免环境。

依据：[Microsoft WebView2 部署文档](https://learn.microsoft.com/microsoft-edge/webview2/concepts/distribution)。未宣称支持 Win7/8、32 位 Windows、原生 ARM64，也未执行真实异机、干净系统或覆盖安装验收。
